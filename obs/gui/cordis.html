二、Cordis 插件框架（cordis.moe）

2.1 简介

Cordis 是一个 元框架（Meta-Framework），拥有高可组合性的插件系统。它的自我定位是 "A Meta-Framework of Spatiotemporal Composability"（时空可组合性的元框架）。

作者 Shigma 是 Koishi（国内最流行的跨平台聊天机器人框架）的作者，Cordis 正是 Koishi v4 的底座。

所谓 元框架，是指它不提供任何业务能力——没有 HTTP、没有数据库、没有调度器，它只提供组装业务能力的范式：插件化、依赖注入、生命周期管理。

核心特点：核心代码不到 3000 行，设计密度极高，把"副作用"和"上下文"两个概念推到极致。

2.2 五个核心概念

  1. 插件（Plugin）：实现 Service 的对象。可以是带有可选 inject 和 apply(ctx) 字段的函数，也可以是 Service 子类，其生命周期由 Cordis 挂载到当前上下文中。
  2. 上下文（Context）：服务的容器。一个服务占据一个稳定的 ctx.<key>（如 ctx.tools、ctx.llm、ctx.sessions）；其他插件通过 key 查找服务，而非导入具体实现。
  3. 依赖注入（inject）：插件声明所需的服务后，会等待这些服务就绪才启动；加载顺序通过服务依赖表达，而非手动编排启动序列。
  4. 类型化事件：服务通过 TypeScript 声明合并注册事件名，然后以 emit、waterfall（瀑布式事件）、parallel 或 serial 方式分发。
  5. 可逆副作用：提示词片段、工具 schema、适配器、提供方和监听器通过 ctx.effect() 或 ctx.on() 安装，reload 和 teardown 时会按预期撤销。

2.4 技术架构

仓库是一个 yarn workspaces monorepo，packages/core 是唯一的核心包，其余八个包全部是插件或工具。core 的运行时依赖只有两个：cosmokit（基础工具库）和 @standard-schema/spec（配置校验的标准接口）。

核心层由五个服务组成，全部挂在同一个 Context 对象上：

  • Fiber：生命周期状态机 + effect 副作用回收，一个插件实例对应一个 Fiber。
  • Registry：插件注册表，负责插件去重与 @Inject 依赖声明。
  • Reflect：服务注册表，同时也是 Context 这个 Proxy 的陷阱处理器。
  • Events：事件系统，提供五种分派模式。
  • Logger：日志缓冲与 exporter 机制。

值得注意的是 core 的 零 I/O 原则：日志输出、配置加载、热更新这些真正跟环境打交道的能力全部以插件形式存在（@cordisjs/plugin-logger-console、@cordisjs/plugin-loader、@cordisjs/plugin-hmr）。这意味着核心可以被嵌入任何运行时——浏览器、CLI、测试环境——而不必携带 Node 专属的依赖。

2.5 关键设计决策

  • 一切皆 effect：副作用显式化，卸载时逆序、串行、可等待地回收。所有副作用都必须以 effect 的形式注册，卸载 = 逆序执行清理函数。
  • 上下文是原型链：派生 O(1)，作用域靠 Symbol 隔离，配置靠链上叠加。派生上下文用 Object.create，同名服务可以在不同作用域共存。
  • 服务变更即重载：epoch 变了就卸载重来，进程不用重启，代码不用写迁移。每个 Fiber 维护一个 epoch 字符串，由它所有注入服务的 uid 拼接而成。
  • 属性拦截式 DI：ctx.db 而不是 ctx.get('db')——Proxy 让依赖注入看起来像原生属性访问，类型通过 TypeScript 模块增强获得。
  • getTraceable：服务方法被其他 Fiber 调用时，this.ctx 会被重绑定到调用方的上下文，实现"同一份代码，在不同的时空上下文里运行"。
  • 配置拦截链 + Standard Schema 校验：ctx.intercept(name, config) 在原型链上叠加配置，配置更新走 waterfall 事件链，所有配置在生效前经过 Standard Schema 校验。

2.6 最小示例

把 Cordis 跑起来的最低要求很轻：Node.js ≥ 22、ESM-only，核心包零 I/O 依赖。最小可运行示例只有三行：

import { Context } from 'cordis'

const ctx = new Context()
ctx.plugin(function (ctx) {
  ctx.on('ready', () => ctx.logger.info('hello cordis'))
})

2.7 部署与生态

  • 实际项目推荐用 create-cordis 脚手架初始化。
  • 生产环境通常配合 @cordisjs/plugin-loader：插件与配置写在 YAML 里，CORDIS_SHARED 环境变量在进程间共享启动信息，改配置后 loader 监听文件变更、走 internal/update 完成热更新。
  • 如果目标是"写一个 Koishi 插件"，那么你已经在写 Cordis 插件了——Koishi 的插件生态与 Cordis 完全同构。
注意：Cordis 目前处于活跃开发阶段（v4 为 rc 版本），API 尚未稳定，可能随时变化（"may change without notice"）。

三、CORDIS 欧盟研究项目数据库（cordis.europa.eu）

3.1 简介

CORDIS 是 Community Research and Development Information Service（社区研究与发展信息服务）的缩写。

CORDIS 是 欧盟委员会关于欧盟框架计划资助的研究创新项目成果的主要信息来源，覆盖从 FP1 到 Horizon Europe 的所有框架计划。

其使命是向专业人士分享研究成果，以促进开放科学、创造创新产品和服务，并刺激整个欧洲的增长。

3.2 主要功能

  • 项目数据库：包含欧盟委员会持有的所有项目信息，包括项目概况表（factsheets）、参与者、报告、交付物以及开放获取出版物的链接。
  • 文章与出版物：包括视频和播客，帮助用户探索相关领域的研究成果。
  • 开放数据下载：可下载整个框架计划的项目数据（Horizon Europe、Horizon 2020、FP7）。
  • 可视化与分析工具：Horizon Dashboard 提供强大的项目与提案数据分析工具。
  • Horizon Collaboration Network：交互式地图，展示 Horizon 框架计划资助的欧盟研究项目之间的合作网络。
  • 月度项目（Project of the month）：每月精选一个在其科学领域具有特别创新潜力的项目。
  • Life after...：追踪项目团队在项目结束后如何进一步推进其研究或产品。

3.3 数据规模

CORDIS 拥有 55,000+ 个欧盟资助项目，涵盖 Horizon Europe 和 H2020 等框架计划。自 1980 年代以来，欧盟通过其框架计划资助了数千个研究项目。

3.4 开放数据

CORDIS 提供以下开放数据下载：

  • Horizon Europe 项目数据（2021-2027）
  • Horizon 2020 项目数据
  • FP7 项目数据

数据集包含六个子集（不同格式）：HORIZON 项目（含参与组织、法律依据、主题信息、项目 URL 等）。

3.5 管理方

CORDIS 由 欧盟出版局（Publications Office of the European Union）代表欧盟委员会的研究创新总司、执行机构和联合企业进行管理，并得到专业承包商在编辑、数据和技术服务方面的支持。

3.6 相关平台

  • Funding and tender opportunities：申请资金和寻找合作伙伴的网站。
  • Kohesio：欧盟凝聚力政策共同资助项目的数据库。
  • Research and Innovation community platform：欧盟委员会研究与创新社区平台。
