# 基座定位与边界 · 人类确认文件（v2）

> 本稿取代《骨架修复.confirmed.md》第 5 条的边界约定；后续修改以本稿为准。

## 壳定位（分层）

1. **GUI = 运行时壳**：插件发现 → 装配 → 弹窗交互，唯一交互运行时。
2. **API = 运行时壳**：无头/外部集成入口，可加载插件并对外暴露 harness 与服务。
3. **CLI / TUI = 观测器壳**：只读 `docs/logs/events.jsonl` 回放/查询/tail，不加载插件。

## 边界（更新）

已批准（承认已实现并保留）：
1. 插件发现 `discoverPlugins`（目录扫描 + dist 加载 + 失败隔离）。
2. 服务权限门（`trusted` / `access` / `highAccessServices`）——基础安全机制，非用户权限系统。
3. 中间件分发器 `Dispatcher`（core 库级能力，emit/waterfall/serial/parallel/bail）。

明确不做：
4. 热插拔（运行时装卸插件，不含启动期过滤）。
5. 路由（按请求路由到插件）。
6. 沙箱隔离（插件与宿主同进程，仅限本地可信插件）。
7. 用户权限系统（登录/角色/授权，区别于服务权限门）。

## 派生的任务方向（逐项先确认后修改）

1. API 壳升级为运行时：复用装配链路（discover → 过滤 → boot），服务以 HTTP 暴露。
2. `dep-missing` 警告在壳侧落地（GUI 显示 + API/CLI 输出）。
3. `Dispatcher` 以 `ctx.dispatcher` 受限视图接入 PluginContext（不重载 `ctx.emit` 观测语义）；待首个协作型插件用例或按"基座能力齐备"要求触发。
4. 通用 UI 桥（插件 api 白名单暴露给弹窗 preload）——需单独安全设计，不并入本轮。

## 边界

不改注册器已锁定契约与单测；不改 Electron 下载机制。
