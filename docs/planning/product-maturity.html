建议下一步（按顺序）

P0 Scope 接到 tools ✓ 已落地

做什么
tools 用 ScopedLayers 归档；prompt-context 已支持 scoped 注册（bind(agent.ctx)）与每步 assemble+apply。
为什么现在
工具仍是全局一张表——多 agent 会串。prompt 组装层已对齐 DSH 薄切片。
动哪里
plugins/tools · plugins/agent-loop
完成标志
两个 agent 各注册同名工具，互不可见；loop 只看见当前 agent scope 内的 tools。有单测锁住。

P0 App：会话列表 + 恢复 ✓ 已落地

做什么
app-ui 左侧列历史 session（读 ~/.wizard-harness/sessions 或 session.list）；点选加载回放/继续聊。
为什么现在
持久化已有，但 UI 每次像新会话——产品体感断层最大的一项。
动哪里
plugins/app-ui · plugins/app-chat（可能要 send 支持指定 sessionId）
完成标志
关窗口重开，能点开昨天的会话并继续发消息；session 条目与磁盘文件一致。

P1 App：流式输出进聊天窗 ✓ 已落地

做什么
llm/delta 或 appChat 流式回调接到 app-ui 消息气泡，边生成边显示；保留取消按钮联动 cancel。
为什么现在
后端已支持 onDelta，前端仍等多段 complete——真模型时等待感明显。
动哪里
plugins/app-chat · plugins/app-ui/src/page.ts · 可能扩展 ui.rpc 为 SSE/增量
完成标志
DeepSeek/OpenAI 回复逐字出现；点取消后流立即停止，trajectory 有 aborted 记录。

P1 App：错误与状态可见 ✓ 已落地

做什么
鉴权失败、超时、tool 失败、loop 步数用尽——在聊天区显示可读文案，右栏 trajectory 可展开详情；不要静默失败。
为什么现在
排错仍靠观测台/trajectory，普通用户不知道去哪看。
动哪里
app-chat 错误映射 · app-ui 展示 · 可选统一 AppChatSendResult.error 契约
完成标志
故意配错 API key，界面明确提示；tool 抛错时 session 与 UI 一致显示失败。

P1 manifest / config schema 校验 ✓ 已落地

做什么
启动时校验 manifest 与 config[pluginId] 形状；畸形 fail-loud，对齐缺口清单 #1。
为什么现在
插件数量上来后，静默畸形最浪费时间；成本低、收益稳。
动哪里
core/src/registrar/validate.ts · 各插件 config 可选 schema 声明
完成标志
故意写坏 provides / tier，boot 即报错并指明插件 id；有单测。

P2 文档与体检同步 ✓ 已落地

做什么
更新 reference/项目体检.md（包数、测试数、scope 模型）；补一篇「不回话怎么查」排错短链；planning/todo.md 开第二阶段表。
为什么现在
文档仍写 4 插件 / 旧 scope 语义，会误导后续自己与他人。
动哪里
docs/ 纯文档，不动运行时
完成标志
体检度量与 pnpm test 一致；排错路径一页纸可跟着点。

P2 观测台：插件启用 / 禁用 / 重载 ✓ 已落地

做什么
GUI 注册表面板可操作：disabled、reload、配合已有 /plugins/scan；状态写回 profile 或运行时 config。
为什么现在
改插件仍要重启整个 Electron；开发迭代摩擦大。
动哪里
obs/core · obs/gui · harness reload API
完成标志
在 GUI 里禁用 hello 后无需重启即不加载；reload 单个插件有事件可观测。

P2 对外 plugin-sdk（契约发布） ✓ 已落地

做什么
定 @wizard-harness/plugin-sdk（contracts + 插件宿主类型重导出）+ 可选 plugin-testing mock harness；写「外部插件最小示例」。
为什么现在
契约层价值在并行开发与对外发布；单仓内不急，但若多人/第三方写插件应提前定边界。
动哪里
新包或 contracts 扩 exports · package.json 发布字段 · 示例 repo/目录
完成标志
空目录只装 sdk + testing，能 typecheck 通过并跑通一个假插件单测，不依赖全仓 plugins。

明确暂缓

没有清晰用例前不做，避免摊大饼：
  • ctx.dispatcher 接入（waterfall/serial）— 等协作型插件
  • 通用任意方法 UI 桥 — 已有 ui.rpc 白名单
  • Goal / Commands / 子 agent fork — DSH 进阶，本地 demo 非必需
  • 插件市场 / P2P / 沙箱 — 确认稿边界外或暂缓
  • 删掉 contracts/ 改 Cordis 式 — 当前独立契约层仍服务解耦与 SDK
