## 要做成什么

需求是**积累经验**，不是挽救单次任务。

需要一个框架，在下面三条**同时成立**时，把经验固化成**刚性执行体**：

1. 业务目标稳定（同一类问题会反复出现）
2. 允许较长冷启动（可以先抽骨架、影子对照、再铸成刚性体）
3. 必须消除执行方差（同一输入不允许因模型心情走出不同思考路径）

比程序灵活（框架可改、格内可挂 AI），比传统 Agent 可控（怎么想事先写死）。  
节点长得可以像工作流，管的不是「AI **做什么**」，而是「AI **想怎么、怎么想**」——这件事必须能可视化。

## 和现有三件事的差别

| | 控制在谁手里 | 节点在管什么 | 失败时 |
| --- | --- | --- | --- |
| 传统 Agent | 判断和节奏都交给 AI | 临场想下一步做什么 | 再问一次 / 加 prompt（挽救这一次） |
| 工作流 | 人画「做什么」 | 任务步骤 | 改流程图；图通常不是思考经验 |
| Skill | 说明书交给 AI，由 AI 决定怎么用 | 较大颗粒的文本经验，常直接注入 | 执行方式仍临场确定 |
| 本框架 | 执行权在框架；人与 AI 只改框架 | 怎么想、按什么想 | **只准优化框架**，不准挽救这一次 |

运行时纪律：执行中不由 AI 确定如何执行；AI 改的是框架。某一格仍可调用 AI（工人，不是导演）。人与 AI **同一个修改口**，不必拆成调参数 / 改步骤 / 格子里调 AI。

## Primitive（当前唯一实现）

**Primitive** = 更小维度的 skill 提示词。含义和目标都与传统 Skill 不同。

| | Skill | Primitive |
| --- | --- | --- |
| 粒度 | 一份可安装说明书 | 一小段思考约束 / 提示 |
| 进模型 | 目录 + alwaysApply **直接注入** | **不准**整包注入 |
| 谁决定用哪几条 | 模型看见说明书后临场用 | **启发式算法或 AI 介入编排** |
| 目标 | 把能力交给 Agent | 把「怎么想」的原子经验管起来，供框架编排 |

本切片只做**仓库**：登记、标签分类、树（分解）、双向链、内部路由预览、可选 `primitive_*` 工具。管理写入、整包注入、影子轨都还没做。编排入口是 `primitive_route`，不能做成第二个 skills。

已认可三类（英文、UI 绿色；旧标签保留）：

| 英文 | 中文 | 这一类在管什么 |
| --- | --- | --- |
| `behavior` | 行为 | 做 / 停 / 禁：这一格允许和禁止的动作 |
| `evaluate` | 评价 | 判：证据够不够、过不过闸、算不算失败 |
| `guide` | 指导 | 想：先看什么、怎么拆、按什么角色想 |

说明文档：[docs/plugins/primitive.html](../plugins/primitive.html)

## 还需要、先不要实现的层

这些是框架要长成的东西，不是 Primitive 仓库的职责。

### 问题分类

编排的入口。先把问题归类，再决定拉哪些 Primitive，而不是让模型对着一堆提示词临场挑。分类稳定，经验才能积在同一条路径上。

### 可视化编排方案

必须能看见「怎么想」，不能只看见「做什么」。最低要能看见：

1. 当前问题类
2. 被编排进来的 Primitive（按 behavior / evaluate / guide 上色）
3. 思考路径（顺序、分岔、停）
4. 评价是否过闸
5. 认知负荷（这一步脑子里同时压了多少）
6. 影子提案相对活图的 diff
7. 训练轮档位（哪些格还挂着 AI）

没有编排可视化，就会退回工作流或 Agent 聊天。

### 评价体系

对一次思考路径打分：有没有违反 Forbid、证据门槛过了没有、方差有没有冒出来。评价的是「想得对不对」，不是「任务有没有做完」。

### 思考模型

可替换的「按什么想」（例如先观察再分岔）。模型是框架里的配置，不是 Agent 人设。挂到图上，不写进 soul.md。

### 认知负荷心理表征

每一步在工作记忆里占多重。编排时用它限制同时激活的 Primitive 数量，避免把小提示词堆回一整份 Skill。可视化必须能标负荷，不能只标节点名。

### 核心概念拆解、归纳、应用

经验要能被拆成概念、收成归纳、再应用到同类问题。Seed Graph 抽的是这类结构，不是步骤清单。

### 元评价体系（Skill 颗粒度）

换位思考：用「对方会怎么想」来审自己的默认。

**default 纠正补丁**：发现默认想法有偏，就打一块补丁；偏掉了就自己装上，偏纠正了就自己卸掉。装/卸的颗粒度是 **Skill 级**（针对某一份能力说明书），不是整个人格、也不是单次对话。元评价管的是补丁该不该在，不是替 Primitive 直接注入上下文。

## 四段机制（未实现）

1. **先验骨架（Seed Graph）**：冷启动。AI **辅助**抽取规则与思考节点，人闸门确认后写入图。骨架是可执行思考图，不是 prompt。
2. **影子模式（Shadow Mode）**：活轨按已确认图执行（刚性）。影子轨同一输入只产出改图提案，不改这一次结果。接受提案 = 积累经验。
3. **阶梯式 AI 依赖衰减（Training Wheels）**：L0 抽骨架 → L1 影子 → L2 格子工人 → L3 去 AI → L4 边缘小模型。档位只降不随便升。
4. **自成长轻量边缘模型**：剩余必须模糊的格子才蒸馏；小模型仍受图调度，不得反向改图。

闸门默认：Freeze 开、Shadow-only 开、Diff-before-apply 开、Variance budget = 0、Cell-AI 关、Seed-extract 关。
