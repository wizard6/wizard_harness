# 注册器（Registrar）功能 · 方案草稿

> 状态：**draft（原始文件）** —— 由 AI 自由发挥，仅供给人类阅读；实现阶段禁止参考本文件。
> 技术栈：TypeScript + Node 22+ + pnpm monorepo（对齐 DSH）。

## 0. 目的（做成后系统/用户得到什么）

- 让 core 能统一 **注册 / 查找 / 枚举 / 注销** 插件，兑现"一切皆插件"。
- 每个注册动作都产生**观测事件**，兑现"一切可追踪可观测"。

## 1. 边界

- 只管"登记 + 生命周期钩子"，**不管插件如何被扫描/发现**（发现/磁盘扫描留待后续确认）。
- 本切片不做：热插拔磁盘扫描、插件间消息路由、权限控制。
- 依赖方向：**core 不依赖插件，插件依赖 core 的类型**（DIP，内化自 3.7）。

## 2. 契约（核心接口，TypeScript）

```ts
interface PluginManifest {
  id: string;            // 全局唯一
  version: string;
  name?: string;
  description?: string;
  inputs?: string[];     // 声明输入
  outputs?: string[];    // 声明输出
  sideEffects?: string[];// 声明副作用
  dependencies?: string[]; // 依赖的其它插件 id
}

interface PluginContext {
  registrar: Registrar;
  config: Config;
  emit(event: PluginEvent): void; // 观测点
}

interface Plugin {
  manifest: PluginManifest;
  register(ctx: PluginContext): void | Promise<void>;
  onStart?(ctx: PluginContext): void | Promise<void>;
  onStop?(ctx: PluginContext): void | Promise<void>;
}

interface Registrar {
  register(plugin: Plugin): Promise<RegisteredPlugin>;
  unregister(id: string): Promise<void>;
  get(id: string): Plugin | undefined;
  list(): Plugin[];
  has(id: string): boolean;
}
```

校验规则：
- `id` 重复 → 抛 `DuplicatePluginError`（防静默覆盖）。
- 无 `manifest` 或无 `register` → 抛 `InvalidPluginError`。
- `dependencies` 引用未注册插件 → 初版**仅警告**，写入观测事件，不强报错。

## 3. 观测与事件

- 每次 `register / unregister / get（命中）/ has` 都 `emit` 一条事件到事件总线。
- 事件格式对齐规范 §8：`{ id, ts, actor: 'core.registrar', action, target, payload, trace_id }`。
- 事件总线为**最小实现**：`emit(event)` → 同步派发订阅者 + 落盘 `docs/logs/events.jsonl`。订阅者可插拔。

## 5. 验收（本切片可操作）

1. 注册一个合法插件 → `get`/`list` 能找到；注册动作产生一条事件。
2. 重复注册同一 `id` → 抛 `DuplicatePluginError`。
3. 非法插件（缺 `manifest` 或 `register`）→ 抛 `InvalidPluginError`。
4. `unregister` 后再 `get` → `undefined`；注销动作留事件。
5. 至少一个订阅者能收到事件；`register/start/stop` 生命周期钩子被按序调用。
6. 核心分支有单测覆盖。

## 7. 分期（建议）

- **P0（本切片 · 已完成）**：registrar + types + 最小事件总线 + 事件持久化（events.jsonl）+ 插件契约（含 api 对外接口 / ui 弹窗页）+ 单测。
- **P1**：**CLI 观测器**（纯 Node）：tail 实时事件流 / 查询 / 回放。
- **P2**：**TUI 观测器**（ink）：交互式实时事件面板。
- **P3**：**GUI 桌面壳**（HTML + Electron）：主窗事件时间线 / 插件状态，+ 每插件轻量独立弹窗页（ui）。
- **P4（后续）**：插件发现/扫描、`dependencies` 强校验、热插拔、权限、插件间路由。

## 8. 风险 / 假设

- 假设：core 尚无事件总线，本切片引入"最小总线"；后续可换更强实现而不改 registrar 契约。
- 风险：`id` 唯一性约定被打破 → 用重复报错兜底，不静默覆盖。
