## 问题清单

### 阻断

1. **观测链路裂成两套。** GUI 事件只在内存；CLI / TUI / API 读 `docs/logs/events.jsonl`。桌面里注册插件，终端观测器看不见。证据：`obs/gui/electron/main.cjs` 只 `subscribe` 数组。
2. **没有真实插件包。** 「一切皆插件」未兑现。根目录 `plugins/` 为空；`obs/plugins` 只有占位 `package.json`；窗口内联 `plugin-a` / `plugin-b`。
3. **Electron postinstall 在 Node 26 解压失败。** `extract-zip@2` 会提前结束，冷启动 `spawn electron.exe ENOENT`。已加 `scripts/ensure-electron.cjs` 兜底；官方 `install.js` 仍不可靠。

### 架构

4. **`obs-spec` / `registrySpec` 四端都未消费。** 契约空转。TUI 自己写了一份 `colorOf`。
5. **React 观测面板写了但 Electron 没用。** `obs/core/src/gui.tsx` 与 `obs/gui/views/registry.tsx` 无运行时引用；真正窗口走 `electron/index.html` + `renderer.js`。
6. **GUI 依赖 `obs-core` 和 `react`，主进程只动态 import core。**
7. **GUI 包没有 tsconfig / typecheck / build。** `pnpm -r typecheck` 会跳过它；`views/registry.tsx` 从未被编译。

### 契约

8. **`manifest.dependencies` 只声明不校验。** `registrar.register` 从不读取该字段。
9. **`onStart` 抛错后插件已入表，但没有 start 事件。** 先 `registry.set` 再 `await onStart`，失败留下半注册状态。
10. **事件总线同步派发。** 一个 sink 抛错会打断后续订阅者（`events/bus.ts` 无 try/catch）。
11. **`readEvents` 遇不到文件就抛错。** CLI / TUI / API 冷启动会挂。
12. **TUI「已注册插件」按 `register` 事件计数。** 注销后数字仍偏高；API `currentPlugins` 才做了净额。
13. **`get` / `list` / `has` 也发观测事件。** 查询本身污染时间线；`has()` 只在 true 时发，不对称。

### 卫生

14. **确认文档路径与仓库不一致。** 确认稿写 `packages/core`，实际是 `core/`。`obs-core` 注释仍写 `observers/gui`。（README 已于本提交补上。）
15. **测试只覆盖 core。** vitest `include` 仅 `core/test/**`，验不到双总线、死面板、空插件。
16. **CLI 的 package exports 指向不存在的类型入口。** `types` → `dist/index.d.ts`，源码只有 `main.ts`。

## 建议修复顺序

1. GUI 订阅 `createFileSink`，与 CLI / TUI / API 共用同一条 jsonl。
2. Electron 装载 `RegistryPanel`，删掉平行的 vanilla 渲染或标明弃用。
3. CLI / TUI / API 使用 `registrySpec`（颜色、摘要），不要各写一份。
4. 在 `plugins/` 放至少一个真实插件包，GUI 改为加载它而不是内联 demo。
5. 补 `onStart` 失败回滚、`dependencies` 警告、`readEvents` 缺文件容错。

## 不算问题的部分

core 的 register / 重复 id / 非法插件 / 注销 / 生命周期顺序，与确认稿一致，测试也锁住了。Electron 二进制缺失已有 `ensure-electron` 兜底，本机窗口可以起来。
