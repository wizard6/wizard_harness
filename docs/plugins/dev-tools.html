dev-tools — 本地编程工具套件

给 agent 一套能在真实工作区写代码的工具。文件工具不出 root；bash 的 cwd 是 root，但命令本身不是路径笼子。全部经 ctx.tools.register 挂到工具注册表。

id: dev-tools provides: devTools inject: tools bundle: app

1. 用途与边界

一句话：sandbox 是玩具目录；本插件对着当前 session.workspace 干活（未设则 WH_WORKSPACE / cwd）。禁止在 loop / app-ui 里直接 fs / spawn。

  • 管：工作区 root、bash / read_file / write_file / str_replace / grep / glob、向 tools 登记、可选 prompt-context 段
  • 不管：OS sandbox、权限询问、并行 tool call、后台 job、JSON schema

2. 服务 API

服务名 DEV_TOOLS_SERVICE = 'devTools'。消费方：ctx.devTools。弹窗只暴露 info。

方法作用
info()fallback root + 本插件登记的工具名（live root 在 session.workspace）

每次 tools.call 用该次 sessionId 的 workspace；没有则 fallback：config.root 或 WH_WORKSPACE，否则 GUI/运行时用 process.cwd()（vitest 无配置时用临时目录）。

3. 登记到 tools 的工具

名字args说明
bashcommand, timeoutMs?cwd = root；默认 30s，上限 120s。不是路径笼子。
read_filepath, offset?, limit?带行号的 utf8；越界抛错
write_filepath, content覆盖写；自动建父目录
str_replacepath, old_string, new_string, replace_all?默认 old_string 必须只出现一次
greppattern, path?, glob?JS 正则；跳过 node_modules/.git/dist
globpattern, path?如 **/*.ts

完整名单以「工具注册表」弹窗的 tools.list() 为准（含 echo / sandbox_* / 本套件）。

4. 给后续 AI

  • 不要把本插件焊进 agent-loop。出口只有 ctx.tools.call。
  • 不要在弹窗声明 tools.call 或 bash 的 rpc。
  • 不要和 sandbox 抢同一份 root；sandbox 仍是 $WH_HOME/sandbox。
  • 不要在这里实现权限门 / OS sandbox。那是后续插件挂 tools 管线的事（本仓库还没有 dsh 那种管线）。
