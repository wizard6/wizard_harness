tools — 工具注册表

登记 / 调用工具。结果只写 session 的 tool-result。不是 agent 循环，也不是权限沙箱。

id: tools provides: tools inject: session 内置 echo / now / upper
用途 服务 API 代码结构 依赖 给后续 AI 已知问题

1. 用途与边界

一句话：唯一允许「执行工具并记入会话」的地方。禁止在 agent 里直接 exec / fetch 当工具。

  • 管：register / list / call、内置 echo / now / upper、观测 register/call/result
  • 不管：agent 循环、权限沙箱、任意 shell

2. 提供的服务

服务名 TOOLS_SERVICE = 'tools'。消费方：ctx.tools 或 ctx.get('tools')。

方法作用失败
register({ name, description?, handler })登记工具无名/无 handler/重名抛错
list()已登记工具（无 handler）—
call(name, args?, { sessionId?, callId? })执行并 append tool-result未知工具抛错；handler 抛错则 ok:false 仍写入
 
await ctx.tools.call('echo', { input: 'hi' })
// session 追加 { kind:'tool-result', data:{ callId, name:'echo', content:'hi', ok:true } }

条目约定：{ callId, name, content, ok }。llm 把 tool-result 投影成 role: tool（tool_call_id = callId）。

4. 依赖 / 期望被依赖

方向对象强度
依赖session必选 inject
依赖logger可选
装配bundles/base默认 profile 挂入
期望被依赖agent-loop循环里只 call 本服务；agent 本身不调 tools
不依赖llm工具执行与模型调用解耦

观测：tools/register、tools/call、tools/result（target = 工具名）。actor = plugin:tools。

5. 给后续 AI 的硬约束

  • 不要在 agent-loop 里绕过本服务直接跑命令；出口只有 ctx.tools.call。
  • 不要把模型 tool-call 解析塞进本插件。那是 agent-loop 切片。
  • 不要再造一份 toolResults[] 当真相源；只 append / replay session。
  • 新工具用 ctx.tools.register，不要改 registry 内核。

6. 已知问题

  • 弹窗仍是说明页。新工具用 ctx.tools.register，不要改 registry 内核。
  • 无参数 JSON schema、无超时、无按 scope 隔离工具表。不要加 shell/文件工具除非单独确认。
  • handler 失败不会 throw 给调用方（ok:false）；未知工具才会 throw。
