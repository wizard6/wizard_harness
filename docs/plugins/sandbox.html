sandbox — 工作区沙箱

文件读写只能落在 root 内。不是插件进程隔离（基座明确不做）。模型经 tools.call：sandbox_ls / sandbox_read / sandbox_write。

id: sandbox provides: sandbox optional: tools bundle: app

1. 用途与边界

一句话：Agent 的工作目录笼子。禁止在 tools / loop / app-ui 里直接 fs 出根。

  • 管：info / resolve / list / read / write、路径越界检查、向 tools 登记三个工具
  • 不管：进程隔离、任意 shell、权限账号、per-session 分桶（当前一份共享 root）

2. 服务 API

服务名 SANDBOX_SERVICE = 'sandbox'。消费方：ctx.sandbox。

方法作用
info()绝对 root
resolve(rel?)相对路径 → 绝对路径；越界抛错
list(rel?)目录条目（file / dir）
read(rel)utf8 文本
write(rel, content)写文本（上限 256KiB）；自动建父目录

root：config.root 或 WH_SANDBOX_DIR，否则 $WH_HOME/sandbox（默认 ~/.wizard-harness/sandbox）。

ui.rpc：info / list（弹窗不放 write）。App demo 顶栏只读 info。

3. 给后续 AI

  • 不要做成 V8/进程沙箱。那是基座边界外。
  • 不要在本插件 child_process / 任意 shell。
  • 模型入口只有 ctx.tools.register 出去的三个工具，不要让 loop 直接 fs。
  • App 窗口不要声明 sandbox.write 的 rpc。
