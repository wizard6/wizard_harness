agent-loop — 编排循环

想 → llm.complete → 若命中文本协议则 tools.call → 再 complete。读写 agent 绑定的 session。不是 live agent，也不拥有 System Prompt。

id: agent-loop provides: agentLoop inject: agent · llm · tools optional: systemPrompt
用途 服务 API 代码结构 依赖 给后续 AI 已知问题

1. 用途与边界

一句话：唯一允许把「模型步」和「工具步」串起来的地方。禁止在 agent / llm / tools 里写循环。

  • 管：run、maxSteps、文本工具协议、观测 start/step/end
  • 不管：live 身份（agent）、System Prompt 存储（system-prompt 插件）、官方 tool_call、流式、调度
const h = ctx.agent.spawn()
ctx.systemPrompt.set(h.sessionId, 'You are brief.')
await ctx.agentLoop.run({ agentId: h.id, prompt: 'echo hi', maxSteps: 4 })
// apply → complete → tools.call('echo') → complete

2. 提供的服务

服务名 AGENT_LOOP_SERVICE = 'agentLoop'。消费方：ctx.agentLoop 或 ctx.get('agentLoop')。插件 id 是 agent-loop。

方法作用失败
run({ agentId?, prompt?, maxSteps? })无 agentId 则 spawn；开始时 systemPrompt.apply(sessionId)；循环 complete / call缺服务 / 未知 agent / 未知工具抛错

经 handle.ctx 取 llm / tools，以便以后 per-agent overlay 生效。历史只在绑定 session。

薄切片工具协议

解析 assistant 文本（会去掉 [mock] 前缀），不是 OpenAI tool_calls：

文本调用
echo <text>tools.call('echo', { input })
tool <name> {json}tools.call(name, json)

mock 会回显 user 内容，所以 user 发 echo hi 时 assistant 为 [mock] echo hi，第一轮会命中。工具结果投影成 [echo] hi 后不再命中，循环结束。

5. 给后续 AI 的硬约束

  • 不要在本插件存 messages[] 或 System Prompt；只在 run 开头 systemPrompt.apply。
  • 不要绕过 ctx.llm.complete / ctx.tools.call 直接 fetch / exec。
  • 不要把官方 tool_call 协议塞进 llm 插件；解析留在本循环，升级协议时只改 parseToolCall。
  • 不要把 createScope / spawn 逻辑搬过来；身份只走 agent。
  • 流式、并行工具、compaction 另开切片。

6. 已知问题

  • 弹窗是说明页，不能从 UI 点 run（通用 UI 桥未做）。
  • 工具协议靠模型「说出」echo/tool 行；真模型未按此格式时不会调工具。
  • llm 仍把 tool-result 投影成 user 文本，不是 tool role。
  • 未知工具会 throw，中断循环（不写成 ok:false 的协议失败——那是 tools.call 对 handler 抛错的行为）。
