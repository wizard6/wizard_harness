agent-loop — 编排循环

想 → llm.complete（带工具表）→ 官方 tool_calls 或文本协议 → tools.call → 再 complete。读写 agent 绑定的 session。

id: agent-loop provides: agentLoop inject: agent · llm · tools optional: systemPrompt
用途 服务 API 代码结构 依赖 给后续 AI 已知问题

1. 用途与边界

一句话：唯一允许把「模型步」和「工具步」串起来的地方。禁止在 agent / llm / tools 里写循环。

  • 管：run / cancel、maxSteps、tool_calls + 文本回退、run.systemPrompt 转交、可选 compactKeep
  • 不管：live 身份（agent）、System Prompt 存储（system-prompt 插件）、调度器
const h = ctx.agent.spawn()
ctx.systemPrompt.set(h.sessionId, 'You are brief.')
await ctx.agentLoop.run({ agentId: h.id, prompt: 'echo hi', maxSteps: 4 })
// apply → complete → tools.call('echo') → complete

2. 提供的服务

服务名 AGENT_LOOP_SERVICE = 'agentLoop'。消费方：ctx.agentLoop 或 ctx.get('agentLoop')。插件 id 是 agent-loop。

方法作用失败
run({ agentId?, prompt?, maxSteps?, systemPrompt? })无 agentId 则 spawn；可选 set+apply；循环 complete / call缺服务 / 未知 agent / 未知工具 / 取消抛错
cancel(agentId)中止该 agent 正在跑的 run（AbortSignal）空闲时无操作

经 handle.ctx 取 llm / tools，以便以后 per-agent overlay 生效。历史只在绑定 session。

工具协议

优先用 llm.complete 返回的 toolCalls（OpenAI 官方）。没有则回退解析 assistant 文本（去掉 [mock] ）：

文本调用
echo <text>tools.call('echo', { input })
tool <name> {json}tools.call(name, json)

mock 在传入 tools 且 user 为 echo … 时直接返回 toolCalls，不再依赖「模型把协议说出来」。文本协议仍给未走官方调用的模型用。

5. 给后续 AI 的硬约束

  • 不要在本插件存 messages[] 或 System Prompt；run.systemPrompt 只转交 systemPrompt.set。
  • 不要绕过 ctx.llm.complete / ctx.tools.call 直接 fetch / exec。
  • 官方 tool_calls 由 llm 解析，循环只消费 result.toolCalls；文本协议留作回退。
  • 弹窗 ui.rpc 只声明 agentLoop.run|cancel。不要把 console.exec 放进任意插件的 rpc。

6. 已知问题

  • 观测台 App demo 走壳白名单 IPC，不经过弹窗。弹窗需 window.wh.call（preload-safe），且方法在 ui.rpc。
  • 未知工具会 throw，中断循环。
  • openai 带 tools 时 complete 非流式；取消靠 AbortSignal。
  • compactKeep 默认 0。大于 0 时每步 session.compact。
