llm — 模型适配器

一次 complete：从 session 投影历史，把 assistant 回复 append 回去。不是 agent 循环。

id: llm provides: llm inject: session 默认 mock
用途 服务 API 代码结构 依赖 给后续 AI 已知问题

1. 用途与边界

一句话：唯一允许「把模型输出写进会话」的地方。禁止在 llm 里自建 messages[] 当真相源。

  • 管：complete（含 tools / onDelta / signal）、mock / OpenAI 兼容 HTTP、观测 request/delta/result
  • 不管：agent 循环、多模型路由、密钥托管

2. 提供的服务

服务名 LLM_SERVICE = 'llm'。消费方：ctx.llm 或 ctx.get('llm')。

方法作用
complete({ sessionId?, prompt?, tools?, signal?, onDelta? })可选写入 user → 投影历史（含 tool role）→ 调模型 → append assistant（可带 tool_calls）。无 session 则 start。
 
await ctx.llm.complete({ prompt: 'hello' })
// → { sessionId, text: '[mock] hello', provider: 'mock' }

config

键默认说明
providermockmock 或 openai。可被 WH_LLM_PROVIDER 覆盖
baseUrl（空）openai 时必填。可被 WH_LLM_BASE_URL 覆盖
apiKey（空）WH_LLM_API_KEY 优先；勿提交真实密钥
modelgpt-4o-miniWH_LLM_MODEL

3. 代码结构（核心方法）

文件核心符号
contracts/src/llm.tsLLM_SERVICE, LlmService.complete
plugins/llm/src/adapter.tsrunModel, mockReply
plugins/llm/src/index.tsapi.complete, asMessages, register
调用链： complete → 取/建 session → 可选 append user → deriveMessages → llm/request → turn/start → runModel → append assistant → llm/result → turn/end

4. 依赖 / 期望被依赖

方向对象强度
依赖session必选 inject
依赖logger可选
装配bundles/base默认 profile 挂入
期望被依赖agent-loop循环里调 complete，不要自己 fetch 模型；agent 本身不调 llm
期望被依赖tools不直接依赖 llm；tool-result 由 tools 写入 session，下次 complete 会读到

观测：llm/request（payload.n = 历史条数）、llm/result（payload.bytes）。actor = plugin:llm。

5. 给后续 AI 的硬约束

  • 不要在 agent-loop 里绕过本服务直接调 HTTP；模型出口只有 ctx.llm.complete。
  • 不要把工具循环塞进本插件。循环是 agent-loop，不是 agent。
  • 密钥只走 config / 环境变量，不要写进仓库或 HTML。
  • 有 tools 时 openai 路径不走 SSE（要等完整 tool_calls）；无 tools 且给了 onDelta 才 stream。

6. 已知问题

  • 弹窗仍是说明页。试跑走观测台 App demo 窗口或 POST /rpc。
  • 默认 mock。openai 无超时/重试；带 tools 时不走 SSE。
  • tool-result 投影为 OpenAI role: tool（带 callId）。mock 在「上一条是 tool」时回 [mock] [name] content，避免再次发出 tool_calls。
  • 模块级 ctx：单实例没问题，测并行会串。
