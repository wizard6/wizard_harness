llm — 模型适配器

一次 complete：从 session 投影历史，把 assistant 回复 append 回去。不是 agent 循环。

id: llm provides: llm inject: session 默认 mock
用途 服务 API 代码结构 依赖 给后续 AI 已知问题

1. 用途与边界

一句话：唯一允许「把模型输出写进会话」的地方。禁止在 llm 里自建 messages[] 当真相源。

  • 管：complete、mock / 可选 OpenAI 兼容 HTTP、观测 llm/request llm/result
  • 不管：流式、tool call、多模型路由、agent 循环、通用弹窗 RPC

2. 提供的服务

服务名 LLM_SERVICE = 'llm'。消费方：ctx.llm 或 ctx.get('llm')。

方法作用
complete({ sessionId?, prompt? })可选写入 user prompt → 投影历史 → 调模型 → append assistant。无 session 则 start。
 
await ctx.llm.complete({ prompt: 'hello' })
// → { sessionId, text: '[mock] hello', provider: 'mock' }

config

键默认说明
providermockmock 或 openai
baseUrl（空）openai 时必填，如 https://api.openai.com/v1
apiKey（空）写入 Authorization；勿提交真实密钥
modelgpt-4o-mini仅 openai 路径使用

3. 代码结构（核心方法）

文件核心符号
contracts/src/llm.tsLLM_SERVICE, LlmService.complete
plugins/llm/src/adapter.tsrunModel, mockReply
plugins/llm/src/index.tsapi.complete, asMessages, register
调用链： complete → 取/建 session → 可选 append user → deriveMessages → llm/request → turn/start → runModel → append assistant → llm/result → turn/end

4. 依赖 / 期望被依赖

方向对象强度
依赖session必选 inject
依赖logger可选
装配bundles/base默认 profile 挂入
期望被依赖agent循环里调 complete，不要自己 fetch 模型
期望被依赖tools不直接依赖 llm；tool-result 由 tools 写入 session，下次 complete 会读到

观测：llm/request（payload.n = 历史条数）、llm/result（payload.bytes）。actor = plugin:llm。

5. 给后续 AI 的硬约束

  • 不要在 agent 里绕过本服务直接调 HTTP；模型出口只有 ctx.llm.complete。
  • 不要把工具循环塞进本插件。tool call 是下一阶段 tools/agent。
  • 流式 / 多提供方路由另开切片，不要顺手做。
  • 密钥只走 config / 环境，不要写进仓库或 HTML。

6. 已知问题

  • 弹窗是说明页，不能从 UI 点一次 complete（通用 UI 桥未做）。试用：观测台 RPC/网关或后续 agent。
  • 默认 mock，不连真模型。openai 路径未做超时、重试、SSE。
  • deriveMessages 只认 data.role + data.content；tool-result 不会进模型上下文（等 tools 切片定投影规则）。
  • 模块级 ctx：单实例没问题，测并行会串。
