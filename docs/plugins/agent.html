agent — live 实例

每个 live agent 一个 createScope，绑定一条 session。管「这次运行是谁、看得见什么」。不是 agent-loop，也不是 prompt-context。

id: agent provides: agent inject: session 不 inject llm / tools
用途 服务 API 代码结构 依赖 给后续 AI 已知问题

1. 用途与边界

一句话：agent 是身份与可见性；循环是 agent-loop；上下文组装是 prompt-context。禁止在本插件里 llm.complete / tools.call / 存 prompt。

  • 管：spawn / get / list / stop、每个实例一个 scope、绑定 session、overlay agent.live
  • 不管：模型调用、工具执行、上下文组装（prompt-context）、maxSteps、流式、调度、多 agent 通信、通用弹窗 RPC
分层： scope 看得见什么 → session 发生过什么 → agent 这次运行是谁（本插件）→ prompt-context 当前指令 → agent-loop 怎么跑

2. 提供的服务

服务名 AGENT_SERVICE = 'agent'。消费方：ctx.agent 或 ctx.get('agent')。

方法作用失败
spawn({ id?, sessionId?, title? })开 scope；无 sessionId 则 start 新会话；overlay provide agent.liveid 重复 / session 不存在抛错
get(id)活实例句柄（含 scoped ctx）无则 undefined
list()id + sessionId，不含 ctx—
stop(id)dispose scope，撕 overlay未知 id 抛错
 
const h = ctx.agent.spawn({ id: 'demo' })
h.ctx.get('agent.live')  // { id, sessionId }，兄弟 scope 互不可见
await ctx.agent.stop(h.id)

句柄上的 ctx 是打标子上下文。agent-loop 应经它调 llm/tools。上下文组装走 prompt-context，不要 setSystemPrompt。

5. 给后续 AI 的硬约束

  • 不要在本插件加 step / run / maxSteps 或解析 echo 协议。那是 agent-loop。
  • 不要 inject llm 或 tools「顺便串起来」。live agent 不需要它们就能 spawn。
  • 不要加 setSystemPrompt。那是 prompt-context（setPersona / section）。不要再造 system-prompt 插件。
  • 不要再造一份 messages[]；历史只在绑定的 session。
  • 每个 live agent 必须 createScope；不要只用 Map 假装隔离。
  • 卸载时 stop 全部活实例，避免 overlay 泄漏。

6. 已知问题

  • 弹窗是说明页，不能从 UI spawn（通用 UI 桥未做）。结构改造第 4 项：列出 live 实例。
  • 进程内 Map，不持久化；session 本身也是内存日志。
  • list() 不按 scope 分桶（应用层用不同 id 区分）。
