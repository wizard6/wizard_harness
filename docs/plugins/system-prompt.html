system-prompt — 当前指令

按 session 登记当前 System Prompt。set 只改登记表；apply 才 append 到 session（llm 从日志投影）。不是 agent 身份，也不是循环。

id: system-prompt provides: systemPrompt inject: session 不 inject agent / llm
用途 服务 API 代码结构 依赖 给后续 AI 已知问题

1. 用途与边界

一句话：唯一允许「登记 / 落实 System Prompt」的地方。禁止写进 agent 或 agent-loop。

  • 管：set / get / apply、按 session 一份当前文本、观测 set/apply
  • 不管：live agent、llm.complete、工具循环、prompt 模板库、按角色多段拼接
ctx.systemPrompt.set(sessionId, 'You are brief.')
ctx.systemPrompt.apply(sessionId)
// session 追加 { kind:'message', data:{ role:'system', content:'You are brief.' } }

2. 提供的服务

服务名 SYSTEM_PROMPT_SERVICE = 'systemPrompt'。消费方：ctx.systemPrompt 或 ctx.get('systemPrompt')。

方法作用失败
set(sessionId, content)登记当前文本，不写 session非字符串 / session 不存在抛错
get(sessionId)读当前登记无则 undefined
apply(sessionId)append system 消息；与上次 apply 相同则跳过session 不存在且已 set 时抛错；未 set 则空操作

当前文本在本插件的 Map；session 只记录「落实过」的 system 消息（append-only）。llm 不读本 Map，只读 replay。

3. 代码结构（核心方法）

文件核心符号

4. 依赖 / 期望被依赖

方向对象强度
依赖session必选 inject
依赖logger可选
不依赖agent / llm / tools按 sessionId 登记即可
装配bundles/base默认 profile 挂入
期望被依赖agent-looprun 开头 apply，不要自己 append system

观测：system-prompt/set、system-prompt/apply（target = session id，payload.bytes）。actor = plugin:system-prompt。

5. 给后续 AI 的硬约束

  • 不要把这套 API 搬回 agent 或 agent-loop。
  • 不要在 llm 里偷偷 prepend 一份不进 session 的 system 消息。
  • 不要改写已写入的 system 条目；换 prompt 就 set + apply，再追加一条。
  • 多模板 / 按 scope 分桶另开切片，不要顺手做。

6. 已知问题

  • 弹窗是说明页，不能从 UI 编辑 prompt（通用 UI 桥未做）。
  • 按 sessionId 一份当前文本，不是按 agent id；多 agent 共用一条 session 会共享 prompt。
  • 进程内 Map，不持久化。
