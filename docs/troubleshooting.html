不回话怎么查

App demo 发消息后没回复、报错或一直转圈——按顺序点，不要跳步。

1. App 窗口本身

  1. 顶栏提示：若显示「上下文组装器未装入」，说明 prompt-context 未加载。产品路径 fail-closed，不能当完整助手跑。检查 profile 是否含 bundles/base，观测台 Config 里是否有 pending。
  2. 发送按钮灰掉：同上，或 promptContext.inspect 失败。先修 boot，不要在 app-ui 里 bypass。
  3. 气泡里的错误：App 已映射鉴权/超时/取消/tool 失败。看 title + hint；详情仍可在右栏 trajectory 展开。
  4. 左侧历史会话：恢复旧会话后 agentId 应复用。若消息乱序，对比 ~/.wizard-harness/sessions/*.json。

2. 观测台注册表（不用重启）

  1. 打开观测台 → Plugins：确认 agent-loop、prompt-context、llm、session、app-chat 均在且非 pending。
  2. Events 搜 inject-pending / boot-fail：缺 inject 会挂起整条链。
  3. 对单个插件点 重载：改 dist 后热替换；失败看 Events 里 reload 相关条目。
  4. 临时 禁用 某插件（如 hello）验证依赖：会写 $WH_HOME/wizard.patch.json，下次启动仍生效。
  5. 扫描：装入尚未注册的新插件目录。

3. 模型与密钥

  • 环境变量：WH_LLM_PROVIDER、WH_LLM_BASE_URL、WH_LLM_API_KEY、WH_LLM_MODEL。密钥放 $WH_HOME/wizard.patch.json 或本机 env，勿提交仓库。
  • mock 模式：未配 openai/deepseek 地址时走内置 mock；user 为 echo … 且 tools 含 echo 时会返回 tool_calls。
  • 鉴权失败：App 气泡应显示「API 密钥」类文案；Events 里看 llm/complete 或 HTTP 错误 payload。

4. 日志与轨迹

  • docs/logs/events.jsonl：GUI / API / CLI 共用事件账本；搜 agentLoop、llm/delta、service-call。
  • docs/logs/app.log：logger 插件落盘（若启用）。
  • App 右栏 trajectory：本轮 observe / think / act 时间线；取消后应有 aborted 记录。
  • HTTP 试跑：pnpm obs:api → /rpc 白名单（见 README WH_EXPOSE）。

5. 仍不行

  • pnpm test：178 项应全绿；红则先修基座再查 App。
  • pnpm build + 观测台 重载 相关插件：dist 与 src 不一致最常见。
  • 点击文件名：打开 code-browser 独立窗口（只读）；窗口内可点「编辑」切到 code-editor。
  • 读插件页：code-browser · code-editor · file-manager
  • 路线图下一项：product-maturity.html P2 以后。
